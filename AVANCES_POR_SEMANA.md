# Avances del Proyecto por Semana

## Semana 1 - Del 06-Oct-2025 al 12-Oct-2025

Durante la primera semana del proyecto se realizó una investigación exhaustiva del formato PPI utilizado por el software Rainview Analyzer para comprender su estructura interna y los desafíos técnicos que presentaba. Se analizó en profundidad el formato de compresión propietario BLOB Qt utilizado en los archivos PPI, identificando la necesidad de desarrollar un algoritmo especializado de descompresión. Paralelamente, se definió la arquitectura del sistema en tres capas principales: PC Remota donde se generan los datos, PC Local con el backend y base de datos, y Frontend para visualización. Se configuraron los entornos de desarrollo necesarios, incluyendo Python 3.9+ con las librerías NumPy y Pillow para procesamiento de datos, Node.js y Express.js para el backend, y React con Vite para el frontend. Además, se completó el diseño inicial de la interfaz de usuario en Figma, estableciendo la tipografía, paleta de colores, estructura de secciones con layout responsivo, y los componentes UI básicos como botones, paneles y controles. Los entregables de esta semana incluyeron el documento de análisis del formato PPI, el diseño completo de interfaz en Figma, y la configuración del repositorio Git para el control de versiones del proyecto.

## Semana 2 - Del 13-Oct-2025 al 19-Oct-2025

La segunda semana se enfocó en el desarrollo del conversor PPI a PNG y la creación del servicio remoto. Se desarrolló completamente el script `advanced_ppi_converter.py` que permite la lectura y parseo de archivos XML embebidos en archivos PPI, la implementación de la función `qt_decompress()` para descompresión de BLOB Qt/zlib mediante la eliminación de padding inicial, extracción del header de tamaño de 4 bytes, y el intento de descompresión con diferentes window bits (15, -15) hasta lograr la validación correcta de los datos descomprimidos. El conversor implementa la transformación de datos de reflectividad (dBZ) a matrices NumPy, aplica una paleta de colores personalizada que va desde celeste claro hasta magenta brillante según la intensidad de precipitación, y genera imágenes PNG con canal alpha (RGBA) para lograr transparencia en la visualización. Se implementó la generación automática de archivos `index.json` con estructura de metadatos que incluye información de timestamp, bounds geográficos y tipo de producto, facilitando la consulta eficiente de archivos convertidos. Adicionalmente, se desarrolló el servicio `radar_server.py` como servidor HTTP básico para servir los PNGs convertidos desde la PC remota, con endpoints REST para consulta de índices y manejo básico de CORS. Los entregables de esta semana fueron el script `advanced_ppi_converter.py` completamente funcional, el servicio `radar_server.py` operativo, la generación automática de `index.json`, y la documentación técnica del algoritmo de conversión.

## Semana 3 - Del 20-Oct-2025 al 26-Oct-2025

La tercera semana se dedicó al desarrollo del visor interactivo. Se realizó la integración completa de React-Leaflet para la visualización de mapas interactivos, configurando el mapa base con tiles de OpenStreetMap, implementando el componente `MapContainer` con controles de zoom y pan, e integrando `ImageOverlay` para la superposición de imágenes radar sobre el mapa. Se desarrolló el componente principal `Visor.jsx` con la estructura completa del visor interactivo, incluyendo el manejo de estado para imágenes y fechas, y la integración con el servicio de API `radarService.js` para la comunicación con el backend. Se diseñó e implementó el panel "Glass" (Panel de Vidrio) con efecto de transparencia que contiene el selector de radar, el selector de fechas disponibles, y los controles principales del visor. Se implementaron los controles básicos de reproducción incluyendo botones Play/Pause, navegación frame por frame con botones anterior y siguiente, y un indicador visual del frame actual. Los entregables de esta semana fueron el componente `Visor.jsx` con mapa interactivo completamente funcional, el panel "glass" con controles principales operativos, y la integración básica con la API remota establecida y probada.

## Semana 4 - Del 27-Oct-2025 al 2-Nov-2025

Durante la cuarta semana se completaron las funcionalidades avanzadas del visor. Se finalizaron los controles de reproducción avanzados con un selector de velocidad de reproducción que permite ajustar la velocidad a 1x, 2x o 4x, una timeline con barra de progreso que muestra el frame actual de manera visual, y navegación avanzada con capacidad de realizar saltos temporales entre frames. Se implementó un sistema completo de filtros horarios que permite filtrar imágenes por rango horario, seleccionar horas específicas del día, y aplicar filtros combinados que integran fecha y hora simultáneamente. Se realizaron optimizaciones significativas de rendimiento mediante la implementación de un sistema de caché de imágenes en el cliente que almacena localmente las imágenes descargadas, pre-carga de frames siguientes para lograr animación fluida sin interrupciones, optimización de re-renderizados utilizando React.memo y useMemo para evitar renderizados innecesarios, y manejo de estados de carga con indicadores visuales que mejoran la experiencia del usuario. Se integraron APIs externas incluyendo Geocoding API para búsqueda de ubicaciones, Weather API para datos meteorológicos complementarios, y soporte para múltiples proveedores de mapas base. Finalmente, se implementaron gráficos de visualización utilizando Recharts para mostrar la distribución de intensidad de precipitación por región y realizar comparaciones temporales de datos. Los entregables fueron el sistema de reproducción completo y funcional, filtros horarios implementados, sistema de caché cliente operativo, integración de APIs externas, y gráficos de visualización de datos.

## Semana 5 - Del 3-Nov-2025 al 9-Nov-2025

La quinta semana se enfocó en el fortalecimiento del backend y la implementación de la infraestructura de servidor. Se desarrolló completamente el backend Node.js/Express.js con configuración del servidor Express.js incluyendo middleware CORS para permitir comunicación entre diferentes orígenes, estructura de carpetas organizada con separación de routes, controllers y services siguiendo buenas prácticas de arquitectura, e implementación de endpoints API REST completos incluyendo `GET /api/radar/:radarId/pngs/viewer-index` para obtener el índice de PNGs para el visor, `GET /api/radar/pngs/:id/image` para obtener imágenes PNG desde almacenamiento, `GET /api/radar/:radarId/pngs` para listar PNGs por radar y fecha, y `GET /api/radar/:radarId/latest` para obtener la última imagen procesada. Se configuró PostgreSQL con la creación del esquema de base de datos completo incluyendo la tabla `radars` para información de radares y la tabla `radar_products` para almacenar metadatos e imágenes PNG en formato BYTEA, creación de índices optimizados en campos clave como radar_id y source_timestamp para mejorar el rendimiento de consultas, e implementación de `radarMetadataRepository.js` como capa de abstracción para acceso a la base de datos. Se desarrollaron servicios de sincronización incluyendo `fileTransferService.js` para transferencia de archivos mediante protocolo SFTP desde la PC remota, `ppiWatcherService.js` para monitoreo automático de nuevos archivos PPI en el sistema de archivos, y `pngUploadService.js` para subida automática de PNGs convertidos a PostgreSQL. Se implementó un proxy Express definitivo con routing inteligente de peticiones, caché de respuestas frecuentes para reducir carga en servidores remotos, y manejo robusto de errores con sistema de reintentos automáticos. Los entregables fueron el backend Node.js/Express.js completamente funcional, API REST completa y documentada, esquema de PostgreSQL implementado y probado, y servicios de sincronización operativos.

## Semana 6 - Del 10-Nov-2025 al 16-Nov-2025

Durante la sexta semana se trabajó en aspectos de seguridad, monitoreo y gestión de usuarios. Se implementó un sistema completo de monitoreo y logging con logging estructurado en formato JSON que facilita el parsing y análisis posterior, definición de niveles de log (DEBUG, INFO, WARN, ERROR) para categorizar adecuadamente los eventos del sistema, almacenamiento en archivos rotativos para gestionar eficientemente el espacio en disco, y desarrollo de un dashboard de monitoreo para visualización de logs en tiempo real que permite identificar problemas rápidamente. Se realizó un hardening exhaustivo de seguridad mediante la implementación de políticas CORS estrictas con lista blanca de orígenes permitidos para prevenir accesos no autorizados, restricción de métodos HTTP permitidos limitando las operaciones posibles, validación rigurosa de credenciales y tokens de autenticación, y protección contra vulnerabilidades comunes como inyección SQL y ataques XSS mediante sanitización de entrada y consultas parametrizadas. Se desarrolló un sistema completo de roles y permisos con implementación de cuatro roles principales: Administrador con acceso completo al sistema, Operador con acceso a funciones operativas, Visualizador con permisos de solo lectura y visualización, y Público con acceso limitado a datos públicos, creación del servicio de autenticación `authService.js` para gestionar usuarios y sesiones, e implementación de control de acceso basado en roles que restringe funcionalidades según el nivel de permiso. Se realizaron mejoras significativas en la interfaz de usuario con navegación mejorada mediante un menú más claro e intuitivo, feedback visual con indicadores de estado más visibles y comprensibles, mensajes de error descriptivos que guían al usuario en la resolución de problemas, y ayuda contextual con tooltips y guías integradas. Adicionalmente, se creó un dashboard público simplificado que permite visualización de datos públicos sin requerir autenticación, muestra gráficos y estadísticas básicas, y proporciona información general del sistema. Los entregables fueron el sistema de monitoreo y logging completamente operativo, políticas de seguridad implementadas y probadas, sistema de roles y permisos funcional, interfaz mejorada con mejor experiencia de usuario, y dashboard público disponible para usuarios sin autenticación.

## Semana 7 - Del 17-Nov-2025 al 23-Nov-2025

La séptima semana se enfocó en la integración completa con PostgreSQL y la implementación de funcionalidades de datos históricos. Se realizó la integración completa con PostgreSQL para almacenamiento de imágenes mediante la modificación de `radarMetadataRepository.js` para incluir el campo `png_data` en todas las consultas necesarias, actualización de la función `getPngIndexForViewer` para filtrar únicamente PNGs que tienen `png_data IS NOT NULL` asegurando que solo se muestren imágenes disponibles, implementación de `getPngImageFromDb` para servir imágenes directamente desde PostgreSQL convirtiendo el formato BYTEA a Buffer para su transmisión, y corrección de URLs para usar endpoints locales en lugar de remotos eliminando problemas de CORS y mejorando la seguridad. Se desarrolló el servicio de conversión automática `ppi_auto_converter_service.py` para ejecutarse en la PC remota con monitoreo automático de nuevos archivos .ppi en tiempo real, conversión automática a PNG con transparencia utilizando el algoritmo desarrollado previamente, y subida automática a PostgreSQL en la PC local mediante conexión remota configurada, estableciendo así un pipeline completamente automatizado. Se implementaron filtros avanzados que permiten filtrar por rango de fechas con selección de fechas de inicio y fin, filtro por fechas específicas para consultas puntuales, filtro por provincia o región geográfica para análisis territorial, aplicación de filtros combinados que integran fecha y provincia simultáneamente, y capacidad de guardar configuraciones de filtros frecuentes para agilizar consultas repetitivas. Se realizaron optimizaciones significativas de consultas mediante la modificación de `getAvailableDates` para filtrar explícitamente registros con `png_data IS NOT NULL`, optimización de índices en la base de datos para mejorar tiempos de respuesta en consultas complejas, e implementación de paginación para manejar eficientemente grandes volúmenes de datos sin sobrecargar la memoria. Se resolvieron problemas críticos del sistema incluyendo la solución del problema de índice vacío donde la API retornaba un array vacío a pesar de existir 17,330 imágenes en la base de datos mediante la corrección de las consultas SQL, corrección del problema de imágenes moradas asegurando que el Content-Type sea correctamente establecido como `image/png`, y solución del problema donde la fecha seleccionada se cambiaba automáticamente implementando lógica para preservar la fecha seleccionada por el usuario durante los auto-refresh del sistema. Los entregables fueron la integración completa con PostgreSQL funcionando correctamente con todas las imágenes almacenadas y accesibles, el sistema de conversión automática operativo en PC remota con monitoreo continuo, filtros avanzados implementados y probados, consultas optimizadas a base de datos con tiempos de respuesta mejorados, y todos los problemas críticos identificados resueltos y validados.
